\begin{abstract}
This report documents Pearls AQI Predictor --- a serverless ML system that forecasts the US Air Quality Index for Karachi up to 72 hours ahead. The system ingests hourly data from the Open-Meteo API, engineers leakage-free features stored in Hopsworks, trains direct per-horizon XGBoost/Random Forest/LSTM models, and serves predictions through a FastAPI + React stack. GitHub Actions automates hourly feature ingestion and daily retraining. The best model (XGBoost) achieves RMSE\,=\,0.92 at +1h ($R^2$\,=\,0.995) and RMSE\,=\,9.41 at +24h ($R^2$\,=\,0.511).
\end{abstract}

\section{Introduction and Data}

This project builds a complete pipeline to predict Karachi's AQI for the next three days: data collection $\rightarrow$ feature engineering $\rightarrow$ feature store $\rightarrow$ model training $\rightarrow$ REST API $\rightarrow$ web dashboard, all automated and serverless.

\textbf{Data source.} All data comes from the \textbf{Open-Meteo API} (free, no key required). It provides hourly weather (temperature, humidity, precipitation, pressure, wind speed/direction) and air quality (PM\textsubscript{2.5}, PM\textsubscript{10}, CO, NO\textsubscript{2}, SO\textsubscript{2}, O\textsubscript{3}, US AQI) for any location. Open-Meteo was chosen over AQICN because it provides weather \emph{and} AQI from a single source and includes a 3-day forecast API needed for multi-day predictions.

\textbf{Backfill.} A one-time backfill populated the Hopsworks feature store with $\sim$3 years of historical data (26,496 hourly rows). The date range is processed in 90-day chunks with 4-day overlap buffers to ensure lag/rolling features compute correctly at chunk boundaries.

\section{Exploratory Data Analysis}

EDA was conducted through a Jupyter notebook and a supplementary script covering stationarity, ACF/PACF, and seasonal decomposition.

\textbf{Target distribution.} The US AQI for Karachi has mean\,=\,88, std\,=\,22, range 41--173. The distribution is right-skewed, concentrated in the ``Moderate'' EPA band (51--100).

\textbf{Temporal patterns.} (1)~AQI is higher in winter (temperature inversions trap pollutants) and lower during monsoon (rain washes out particulates). (2)~A diurnal peak occurs around 7--8\,PM ($\sim$96 AQI), driven by rush-hour emissions and boundary-layer collapse. (3)~No meaningful day-of-week pattern exists.

\textbf{Stationarity.} The ADF test confirmed the raw AQI series is stationary ($p \ll 0.05$), so no differencing is needed.

\textbf{Autocorrelation.} ACF remains significant up to 72h (ACF\,=\,0.440), and PACF shows direct influence at 24h, 48h, and 72h lags. This informed the lag feature design.

\textbf{Key correlations.} 6h rolling AQI (0.96), PM\textsubscript{2.5} (0.72), wind speed ($-$0.41). Hour and month show near-zero \emph{linear} correlations despite strong cyclical effects, motivating sin/cos encoding.

\section{Feature Engineering}

The \texttt{build\_features.py} module transforms 13 raw columns into $\sim$60 features:

\begin{enumerate}
  \item \textbf{Time features:} Sin/cos encoding of hour, month, day-of-week; weekend flag.
  \item \textbf{AQI lags:} 1h, 3h, 6h, 12h, 24h, 48h, 72h (48h/72h added per ACF analysis).
  \item \textbf{AQI rolling stats:} Rolling means (3--48h), std (6h, 24h), min/max (24h), EWM (12h half-life). All shifted by 1h to avoid leaking the current value.
  \item \textbf{Pollutant lags/rolling:} Past values of PM\textsubscript{2.5}, PM\textsubscript{10}, CO, NO\textsubscript{2}, SO\textsubscript{2}, O\textsubscript{3}. \textbf{Raw current-timestep pollutant values are dropped} to prevent target leakage (US AQI is a deterministic function of these concentrations).
  \item \textbf{Trend features:} AQI first-differences (1h, 3h, 6h, 24h) and deviation from rolling means.
  \item \textbf{Weather interactions:} Wind u/v vector decomposition, temperature$\times$humidity index, cumulative precipitation (6h), rain-in-last-24h flag.
\end{enumerate}

Features are stored in \textbf{Hopsworks Feature Store} (free tier, HUDI format) with \texttt{time} as the primary key. Version 2 of the feature group contains the leakage-free features.

\section{Modeling Approach}

\textbf{Direct multi-horizon strategy.} Instead of recursively feeding +1h predictions forward (which accumulates error over 72 steps), a \emph{separate model} is trained for each horizon: +1h, +6h, +12h, +24h, +48h, +72h. Intermediate hours are linearly interpolated.

\textbf{Forecast weather integration.} Open-Meteo provides 3-day weather forecasts, legitimately available at inference time. The training pipeline shifts weather columns by $-h$ to create forecast features and also computes weather \emph{deltas} (forecast $-$ current), capturing expected meteorological change.

\textbf{Horizon-specific feature pruning.} For long horizons ($\geq$24h), short-term features (1h/3h lags, short rolling stats) are dropped because they carry no signal that far ahead. The model is anchored on 24h diurnal lags, rolling means, and forecast weather.

\textbf{Models evaluated} (all three trained per horizon):
\begin{itemize}
  \item \textbf{XGBoost:} 500 trees, depth 6, lr 0.05, early stopping (20 rounds).
  \item \textbf{Random Forest:} 300 trees, depth 15.
  \item \textbf{LSTM (PyTorch):} 2-layer, 128 hidden, 48h sliding window, Huber loss ($\delta$=10), LR scheduling.
\end{itemize}

Data split: chronological 70/15/15 (train/val/test), no shuffling.

\section{System Architecture and Deployment}

\textbf{Backend.} A FastAPI application serves four endpoints: \texttt{/api/current} (live AQI + EPA category + pollutants), \texttt{/api/forecast} (72h direct forecast), \texttt{/api/history} (48h observations), and \texttt{/api/analytics} (model metrics + SHAP data). A 5-minute TTL cache avoids redundant API calls. Deployed on \textbf{FastAPI Cloud}.

\textbf{Frontend.} React + TypeScript + Vite + Tailwind CSS v4 + Recharts dashboard with: live AQI hero card, pollutant matrix, 72h forecast chart, 48h history chart, and SHAP explainability panel. Deployed on \textbf{Vercel} with API proxy rewrites.

\textbf{CI/CD.} GitHub Actions runs two scheduled jobs:
\begin{itemize}
  \item \textbf{Feature pipeline} (hourly): fetches 14 days of actuals + 3 days of forecasts, engineers features, upserts to Hopsworks. Uses a minimal dependency set (no PyTorch/XGBoost).
  \item \textbf{Training pipeline} (daily at 02:00 UTC): retrains XGBoost and RF models, commits updated artifacts to the repo, which triggers FastAPI Cloud auto-redeploy. LSTM is disabled in CI (slow, no accuracy gain).
\end{itemize}

\section{Key Decisions and Limitations}

\textbf{Key design decisions:}
\begin{enumerate}
  \item \emph{Direct vs.\ recursive forecasting} --- avoids error accumulation; enables horizon-specific feature selection.
  \item \emph{Dropping raw pollutants} --- prevents target leakage since AQI is deterministic from pollutant concentrations.
  \item \emph{Sin/cos time encoding} --- preserves temporal proximity (hour 23 $\approx$ hour 0).
  \item \emph{Separate CI requirements files} --- feature pipeline installs only 6 packages; training adds XGBoost/scikit-learn.
  \item \emph{Auto-commit models} --- GitHub Actions commits retrained artifacts $\rightarrow$ triggers cloud redeploy automatically.
  \item \emph{PyTorch instead of TensorFlow} --- TensorFlow has a protobuf version conflict with Hopsworks on Python 3.13.
\end{enumerate}

\textbf{Limitations:} (1)~Long-horizon accuracy is inherently limited ($R^2 \approx 0.13$ at +72h). (2)~Single-city support. (3)~No automated hyperparameter tuning.

\textbf{Future work:} Satellite aerosol data integration, push alerts for hazardous forecasts, conformal prediction intervals, multi-city extension.
